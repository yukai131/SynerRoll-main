# BUG-003：能流图缺少负荷跟踪与读图说明

> 修复日期：2026-09-28
> 状态：待回归验证
> 严重程度：P3（优化建议）
> 影响范围：任务结果分析页的能流平衡图显示方式与读图信息；不影响仿真计算、结果数据和其他分析模块

---

## 1. 问题描述

**用户操作路径**：

1. 创建并完成包含电源、电负荷和储能的仿真任务。
2. 进入任务的“能流平衡分析”页面。
3. 查看各时层的电母线堆叠图。

**预期行为**：除现有能流平衡视图外，用户可以切换到负荷跟踪视图，将电负荷作为横轴上方的折线，与风电、光伏、火电和储能放电等供给侧出力直接比较；储能充电继续保留在横轴下方。图表应明确标识电源侧、负荷侧、储能充放电归属、纵坐标单位和两侧构成含义，并明确区分左侧功率（kW）与右侧累计电量（kWh）。

**实际行为**：页面只有一种能流平衡堆叠图。分时电负荷与储能充电等项目共同显示在横轴下方，无法直接观察供给侧堆叠出力对电负荷的跟踪关系；图内也缺少功率单位和储能方向等说明，同一储能设备的充放电系列名称容易混淆；电网购电和售电序列也共用“电网”名称，导致 ECharts 将两个方向合并为一个图例；主图按当前可见系列顺序动态配色，右侧累计电量又独立重新配色，导致切换模式后同一系列颜色变化，且主图与右侧色块不一致；右侧构成值由功率样本直接求和，未结合时层步长换算和标明累计电量单位。

**检查位置 2**：`app/pages/tasks/index.vue` — 能流平衡分析区

### 2.3 日志结果

构建输出关键摘录：

```text
✓ Client built in 11014ms
✓ Server built in 3532ms
[nitro] ERROR Error: EPERM: operation not permitted, readlink 'C:\Users\Administrator'
```

客户端和服务端代码编译完成；Nitro 最终打包阶段因当前 Windows 环境无权对用户目录执行 `readlink` 而中断。该错误发生在 `node-externals` 的 `buildEnd` 阶段，不是本次 Vue 模板或 TypeScript 编译错误。

### 2.4 分析与排除

**H1 被确认**：原实现只创建 `bar` 系列，没有任何总负荷 `line` 系列。

**H2 被确认**：原页面没有能流显示模式状态，所有母线和时层固定使用同一种图表口径。

**H3 被确认**：原实现直接遍历完整 `sinkVars`，分时电负荷和储能充电没有显示层面的独立集合。

**H4 被确认**：原图表没有电源侧/负荷侧区域标识，纵坐标没有功率单位，右侧贡献度区域没有标题，储能充电和放电使用相同设备名称。

**H5 被确认**：`E_GRID_in`（向电网上送、售电）和 `E_GRID_out`（从电网购入、购电）均直接使用电网设备名称，两个系列同名后被 ECharts 合并为一个图例项。

**H6 被确认**：右侧贡献度原计算为 `Σ|P(t)|`，没有乘以时间层步长，得到的数值不能直接标记为 kWh。

**H7 被确认**：主图使用递增的 `colorIdx` 按当前可见系列分配色板；负荷跟踪模式移除电负荷柱后，后续负侧系列会占用不同色号。右侧贡献度则从色板起点独立配色，因此没有复用主图中同一变量的颜色。

后端结果缺失或计算错误被排除：当前 `liveData` 和母线连接变量已经能支持原有负荷柱显示，本次只需要调整前端展示，不需要修改任务接口或仿真模型。

## 3. 根因确认

根因是能流图最初只设计了“供给侧正向堆叠柱 + 用能侧负向堆叠柱”这一种展示方式，页面和图表组件均没有显示模式概念，也没有将 `E_ELOAD` 与其他负侧变量区分。修复后的对应代码位置位于 `app/pages/tasks/index.vue:121` 和 `app/components/EnergyFlowChart.vue:107`、`app/components/EnergyFlowChart.vue:222`、`app/components/EnergyFlowChart.vue:241`；修改前实现可通过本文第 2.2 节代码及版本差异追溯。

## 4. 修复方案

### 4.1 页面增加模式切换

在任务结果的能流分析区增加页面级 `energyFlowDisplayMode`，默认值为 `balance`。用户可以通过“能流平衡模式”和“负荷跟踪模式”两个按钮切换，所有母线及时层图表同步响应。

```typescript
type EnergyFlowDisplayMode = 'balance' | 'loadTracking'

const energyFlowDisplayMode = ref<EnergyFlowDisplayMode>('balance')
```

该状态仅用于当前页面显示，不写入项目、任务或后端数据。

### 4.2 图表区分分时电负荷

图表通过稳定变量前缀 `E_ELOAD` 识别分时电负荷，不依赖用户可修改的组件中文名称。

```typescript
function isElectricLoadVariable(varName: string): boolean {
  return varName === 'E_ELOAD' || varName.startsWith('E_ELOAD_')
}
```

在能流平衡模式下，仍使用完整负侧变量集合，保持原显示逻辑。在负荷跟踪模式下，仅从负侧柱及负侧贡献度中排除分时电负荷，储能充电和其他用能变量保持原位置。

### 4.3 生成电负荷折线

负荷跟踪模式按当前时层、仿真时间范围和时间点汇总同一母线上的全部分时电负荷：

```text
电负荷(t) = Σ |E_ELOAD_i(t)|
```

汇总结果以正值非平滑折线显示在横轴上方，不加入供给侧堆叠。缺失时间点使用 `null` 形成断点，不把缺失数据伪造为零值。折线绘制层级高于柱体，以便直接对比电源出力。

### 4.4 无电负荷母线处理

如果母线不包含 `E_ELOAD`，则不生成电负荷折线，也不改变该母线原有负侧变量。这避免将热、氢等其他载能负荷误判为电负荷。

### 4.5 增加正负侧及模式说明

强化图表零轴，并在页面增加统一文字说明，明确零轴上方为电源侧、下方为负荷侧，储能放电属于电源侧、储能充电属于负荷侧。图内“电源侧（正值）”和“负荷侧（负值）”独立标注经后续评审撤回，最终版本不保留这两处标注及箭头。

负荷跟踪模式额外提示：电负荷折线放置在零轴上方只是为了与电源出力直接比较，不代表其属于电源侧，也不计入电源侧堆叠或构成比例。

### 4.6 完善图例、构成标题和单位

- 电储能相关的 `_in`、`_out` 变量分别显示“（充电）”和“（放电）”，避免同一设备产生同名图例。
- 电网 `E_GRID_in` 显示为“电网（售电）”，`E_GRID_out` 显示为“电网（购电）”；图例、Tooltip 和右侧累计电量构成统一使用该名称，避免双向序列被合并或混淆。
- 电负荷折线显示为“电负荷”。
- 右侧两个贡献度区域分别增加“电源侧构成”和“负荷侧构成”标题。
- 纵坐标增加“功率（kW）”，零值刻度显示为 `0 kW`，Tooltip 数值补充 `kW`。

### 4.7 区分功率与累计电量

主图标题增加“功率”，纵坐标和 Tooltip 使用 `kW`。右侧标题改为“电源侧累计电量（kWh）”和“负荷侧累计电量（kWh）”，悬浮提示也使用 `kWh`。

右侧累计电量按项目当前时间层的 `step` 计算：

```text
累计电量（kWh） = Σ |功率（kW）| × 时层步长（min）÷ 60
```

页面把当前时层步长以分钟传入图表。右侧百分比以换算后的累计电量为分母计算，避免把功率样本之和直接表述为电量。

### 4.8 固定能流图系列颜色

能流图按完整的源、荷变量集合建立一次稳定的“变量—颜色”映射，显示模式只控制系列是否显示，不参与颜色编号。主图柱形、图例、Tooltip 和右侧累计电量构成均复用该映射；贡献度排序只改变条目位置，不改变颜色。负荷跟踪模式的总电负荷折线继续固定使用黑色。

本次颜色统一仅作用于能流图组件，不修改公共主题和其他结果图表，避免超出本问题范围进行全平台样式重构。

## 5. 预期结果与副作用

| 指标 | 修复前 | 预期修复后 |
|---|---|---|
| 能流显示模式 | 只有能流平衡模式 | 可在能流平衡与负荷跟踪模式间切换 |
| 分时电负荷显示 | 横轴下方的负值堆叠柱 | 负荷跟踪模式下汇总为横轴上方折线 |
| 储能充电显示 | 横轴下方 | 两种模式下均保持横轴下方 |
| 储能放电显示 | 横轴上方供给侧 | 两种模式下均保持横轴上方供给侧 |
| 多个分时电负荷 | 分别参与负侧堆叠 | 按相同时间点汇总成一条电负荷折线 |
| 原有默认行为 | 能流平衡堆叠图 | 默认仍为能流平衡堆叠图 |
| 正负侧含义 | 依赖用户自行理解 | 页面文字说明电源侧、负荷侧及储能充放电归属 |
| 储能图例 | 充电、放电可能使用相同设备名 | 分别补充“（充电）”“（放电）” |
| 电网图例 | 购电、售电共用“电网”，合并为一个图例 | 分别显示“电网（购电）”“电网（售电）” |
| 系列颜色 | 按当前可见顺序分配，切换模式后可能变化 | 按完整变量集合固定，模式切换不改变颜色 |
| 主图与右侧颜色 | 两处独立配色，同一系列可能不同色 | 共用变量颜色映射，保持一致 |
| 纵坐标与提示单位 | 未明确标注 | 纵坐标、零值刻度和 Tooltip 明确使用 kW |
| 贡献度区域 | 无区域标题 | 标记为“电源侧构成”“负荷侧构成” |
| 主图物理量 | 依赖纵轴单位判断 | 标题明确为功率，使用 kW |
| 右侧物理量 | 功率样本直接求和，单位不明确 | 按时层步长换算累计电量，使用 kWh |

**副作用与限制**：

- 显示模式是页面临时状态，刷新页面后恢复为默认的能流平衡模式。
- 负荷跟踪模式只聚合 `E_ELOAD`，不会把储能充电、电解槽耗电等其他用能项目重复计入电负荷；这些项目继续作为负侧柱显示。
- 不包含分时电负荷的母线不会出现电负荷折线。
- 负荷跟踪模式的电负荷折线虽然位于正值区域，但仅用于对比，页面已增加专门说明以避免语义误解。
- 累计电量依赖项目时间层 `step`；当步长格式无法解析时使用 60 分钟兜底，并保持图表可用。
- 当前统一颜色映射限定在单个能流图的完整变量集合内；本次不调整其他分析图表的现有色板。
- 本次未修改后端、仿真模型、结果接口、公共主题或其他分析模块。
