# BUG-005：候选工作目录硬删除遇文件锁拖死整个规划任务

> 修复日期：2026-09-28
> 状态：已修复、待回归验证（Julia 侧本机无运行时，需开发机重跑规划任务确认）
> 严重程度：P0 — 首个候选评价后的目录清理即可使整个规划任务失败
> 影响范围：Windows 开发机/服务器上所有容量规划任务（评价产生 SQLite 句柄后清理必现风险）

---

## 1. 问题描述

**用户操作路径**：

1. 启动 Julia 后端与前端，创建并启动一个容量规划任务
2. 第一个候选（建议解）仿真与经济评价完成
3. 任务状态变为 `failed`，结果页报错

**预期行为**：非最优候选的临时工作目录清理失败不应影响任务，评价继续。

**实际行为**：

```
Error: capacity planning failed
│   planning_id = "cp-513aa9f0-..."
│   exception =
│    IOError: unlink("...\work\d83992000ea03b6c\scenarios\scenario-1\timeseries.db"):
│    resource busy or locked (EBUSY)
│    Stacktrace:
│     [7] fitness(raw_values::Vector{Float64}) @ optimization_runner.jl:386
│     [8] (::var"...")() @ optimization_runner.jl:412   # fitness(suggested)
```

## 2. 定位过程

### 2.1 初始假设

| 编号 | 假设 | 对应症状 | 初始置信度 |
|---|---|---|---|
| H1 | 候选 `work_dir` 下的 `timeseries.db` 仍被 SQLite 句柄占用，Windows 拒绝删除，`rm` 直接抛出 | EBUSY 指向该 db 文件，异常抛在 `rm` 行 | ⭐⭐⭐⭐⭐ |
| H2 | 路径/权限问题导致删不掉 | 也会 IOError，但 EBUSY 语义不符 | ⭐ |

### 2.2 验证

静态阅读 + 实际报错互证，无需插桩：报错行 `optimization_runner.jl:386`（修复前）即 `rm(work_dir; recursive=true, force=true)`；`timeseries.db` 由 `evaluate_snapshot`/`evaluate_scenario_operating_cost` 打开，句柄释放依赖 GC finalize，与 `GC.gc(false)+sleep(0.2)` 不保证时序。用户贴出的完整 IOError 证实 **H1**，排除 H2（EBUSY 非权限语义）。

## 3. 根因确认

`fitness` 内对非最优候选的清理是**硬删除、失败即抛**（`optimization_runner.jl:385-387`，修复前）。评价完成后该候选的 SQLite 句柄常未 finalize，Windows 对打开中的文件拒绝 unlink（EBUSY），异常穿过 `bboptimize` 使 `run_capacity_optimization!` 整体失败、任务标记 `failed`。评价结果本身已落库，纯因"倒垃圾失败作废整场考试"。

## 4. 修复方案

新增 `_safe_rm_workdir(path)`（`optimization_runner.jl:172`）：不存在直接返回；删除失败时 `GC.gc(true)` 促 finalize 后重试，共 3 次（间隔 0.5s）；仍失败仅 `@warn` 并保留残留目录，**绝不抛出**。两处调用点（替换最优时的旧目录清理、非最优候选清理）均改走该封装。

```julia
# 修改前：
elseif isdir(work_dir)
    rm(work_dir; recursive=true, force=true)
end

# 修改后：
else
    _safe_rm_workdir(work_dir)
end
```

## 5. 预期结果与副作用

| 指标 | 修复前 | 预期修复后 |
|---|---|---|
| 首候选清理遇锁 | 任务 failed | 重试后删除成功，或告警残留、任务继续 |
| 任务完成率 | 规划常被清理中断 | 不再因清理失败中断 |

**副作用**：残留目录可能占用磁盘（`@warn` 已提示路径，可手工清理）；失败路径上的 `GC.gc(true)` 全量回收仅偶发执行，对性能影响可忽略。

## 6. 调试日志处理建议

保留 `@warn "候选工作目录清理失败..."`（残留目录的唯一可见信号），不降级不删除。
