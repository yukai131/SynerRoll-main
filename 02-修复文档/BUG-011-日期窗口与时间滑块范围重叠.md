# BUG-011：日期窗口与时间滑块范围重叠

> 修复日期：2026-10-04  
> 状态：待回归验证  
> 严重程度：P1 — 长时序结果无法分层选择查看范围  
> 影响范围：运行总览、设备出力分析、系统灵活性量化评估、设备灵活性量化评估、能流平衡分析及能流设备明细

---

## 1. 问题描述

**用户操作路径**：

1. 创建一个具有自然日期的多日或全年仿真任务。
2. 进入任一结果时序分析页面。
3. 通过日期输入框选择日期，再拖动下方双端滑块查看小时级数据。

**预期行为**：日期控件先确定粗粒度日期窗口；滑块只在该窗口内细调具体时刻。默认日期窗口为任务实际仿真起止日期。能流平衡页面应提供同样的交互，能流明细应随最终可见时段同步统计。

**实际行为**：已有页面的日期控件与滑块直接修改同一组起止值，功能重叠；滑块仍以完整任务为边界。能流平衡页面没有日期和滑块控件。能流明细表另有一行源侧/负荷侧分组栏，三列表头宽度不一致。

---

## 2. 定位过程

### 2.1 初始假设

| 编号 | 假设 | 对应症状 | 初始置信度 |
|---|---|---|---|
| H1 | 日期控件与滑块绑定了同一组响应式状态 | 修改日期和拖动滑块表现完全相同 | 高 |
| H2 | 设备出力图百分比换算忽略任务非零起点 | 非零起点任务的滑块位置可能产生偏移 | 中 |
| H3 | 能流图仍直接使用任务起止时间过滤数据 | 页面无法进行局部时间查看 | 高 |

### 2.2 调试与检查方案

本次问题属于确定性的前端状态绑定问题，没有插入运行时日志，以免给高频图表刷新路径增加噪声。使用静态检索核对各组件的绑定关系，并通过生产构建验证模板和 TypeScript 编译：

```powershell
rg -n "CalendarRangeInputs|DualRangeSlider|rangeStart|rangeEnd" app/components
npm run build
git diff --check
```

预期：日期组件拥有独立的日期范围状态；滑块 `min/max` 绑定日期范围而不是完整任务范围；能流图使用滑块最终范围过滤主图和明细统计。

### 2.4 分析与排除

**H1 被确认**：各图表原先将 `CalendarRangeInputs` 和 `DualRangeSlider` 同时绑定到 `rangeStart/rangeEnd`，不存在上层日期窗口。

**H2 被确认**：设备出力图使用 `maximumMinute * percentage`，没有加回 `minimumMinute`；任务起点不为零时会发生偏移。

**H3 被确认**：能流主图与 contribution 统计直接读取 `simStartTime/simEndTime`，没有局部可见范围状态。

---

## 3. 根因确认

结果页只有一层时间范围状态，日期控件和滑块都在修改最终图表范围，因此无法形成“日期粗选、时刻细调”的父子约束。设备出力图的百分比换算还默认时间轴从 0 开始。直接证据位于 `app/components/TaskSeriesChart.vue:29`、`app/components/FlexibilitySeriesChart.vue:36`、`app/components/DeviceFlexibilityChart.vue:23`、`app/components/device-output/DeviceOutputChart.vue:132` 和 `app/components/EnergyFlowChart.vue:144`。

---

## 4. 修复方案

### 4.1 两级时间范围

各时序图维护两组范围：

```typescript
const dateRangeStartMinutes = ref(0)
const dateRangeEndMinutes = ref(DAY_MINUTES)
const rangeStartMinutes = ref(0)
const rangeEndMinutes = ref(DAY_MINUTES)
```

- 日期范围默认使用任务仿真起止时间；
- 修改日期后，最终滑块范围重置为所选日期窗口全宽；
- `DualRangeSlider` 的 `min/max` 改为日期窗口起止值；
- 滑块最终范围继续负责图表数据、横坐标和明细统计过滤；
- 日期终止日按包含该自然日处理，内部仍使用半开区间。

### 4.2 设备出力百分比换算

百分比到分钟的换算改为基于任务实际跨度：

```typescript
const timelineSpanMinutes = computed(() => maximumMinute.value - minimumMinute.value)
const rangeStartMinute = computed(() =>
  minimumMinute.value + timelineSpanMinutes.value * props.zoomStart / 100
)
```

反向换算同样减去 `minimumMinute`，避免非零仿真起点偏移。

### 4.3 能流平衡与明细表

- 能流平衡主图增加日期选择和双端滑块；
- 环形图与设备电量明细使用滑块最终时段重新统计；
- 删除源侧、荷侧独立分组栏；
- 两张表改成等宽三列，第一列表头分别为红色“源侧设备名称”和蓝色“荷侧设备名称”。

## 5. 预期结果与副作用

| 指标 | 修复前 | 预期修复后 |
|---|---|---|
| 日期控件作用 | 直接修改最终时刻范围 | 确定滑块可操作的日期窗口 |
| 滑块边界 | 完整任务范围 | 当前所选日期窗口 |
| 默认范围 | 受数据已返回长度影响 | 任务实际仿真起止日期 |
| 能流局部查看 | 不支持 | 主图、环形图、明细表同步响应 |
| 明细表列宽 | 内容自适应，不均匀 | 左右表均为等宽三列 |

**副作用**：每次修改日期时会主动把滑块恢复为该日期窗口全宽，这是用于避免保留一个落在新日期窗口之外的旧小时范围。任务运行中尚未返回的时段仍可出现在日期窗口中，图表对应区间可能暂时为空，符合“任务配置范围优先”的交互约定。
