## 2. 约束语义（economicConstraints）

- `interestRatePercent`（启用）→ 覆盖折现率 = threshold/100；
- `taxRatePercent`（启用）→ 覆盖所得税率；
- `lifecycleYears`（启用）→ 覆盖评价年限；
- `targetIrrPercent`（启用）→ IRR 低于阈值时惩罚 = 差额 × CAPEX，叠加进 fitness。
- 实现：`_apply_economic_constraints!` + `_with_lifecycle_params`（struct 整体重建，避免可变共享）。

## 3. 近似与遗留（评审输入）

1. **真多目标（Pareto）未实现**：当前为单目标切换 + 约束惩罚加性叠加；多目标归档/前沿展示待 C-405 方案比较时评估。
2. **技术约束未接线**：消纳率/绿电占比/购电占比/稳定性需从仿真时序后验计算（发电量/购电量/slack），建议统一在"后验指标层"与 F 线灵活性一并实现，避免在经济评价器里重复解析时序。
3. **惩罚函数近似**：IRR 差额 × CAPEX 为业务可读近似，非 NumericPolicy 推导值。
4. fitness 目标维度不进入 `economicEvaluatorVersion`（任务 config 冻结，同任务内不变）；跨任务对比时以 breakdown.objectiveFitness 与 warnings 为准。
