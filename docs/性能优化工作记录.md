# SynerRoll 性能优化工作记录

> 2026-10-19 更新：当前实现与复测请参阅 [仿真性能优化](./性能优化-2026-10-19.md)。下文数值为历史版本记录。

> 范围：仿真任务「越跑越慢」、前端滚动刷新卡顿、首次打开/建任务冷启动、求解器选项  
> 工程路径：`D:\Downloads\SynerRoll-main\SynerRoll-main`（以该目录为准）  
> 结论前置：**求解约 0.5～1.3s/步且均匀**；历史变慢主要在 **时序库写入/查询** 与 **前端渲染**。  
> 约束：**不改业务语义**（调度结果、灵活性指标口径、全年明细行均保留）。

---

## 1. 现象与目标

| 现象 | 说明 |
|---|---|
| 8760h 仿真 | 前 4.5 个月约 10 分钟，之后同等日历长度更久 |
| 前端 | 期望约 1s 滚 1 天；曾 5s 滚 2～3 天，甚至图不动 |
| 资源 | 任务管理器 CPU/内存充足 |
| 冷启动 | 重启 Julia 后首次「打开项目」约 6s、「创建任务」约 3s，第二次明显变快 |
| 求解器 | 曾只剩 HiGHS，需补回 COPT |

**目标：** 定位瓶颈；性能优化不破坏业务；前端跟得上求解；冷启动可接受或可预热。

## 2. 排查方法

### 2.1 埋点体系

| 位置 | 内容 |
|---|---|
| Julia `perf_*` | 开发埋点；`perf_probe.jl` 当前可为空实现 |
| 前端 `[Probe]` | `getData/merge/flex/state/cycle`、`rows`、`julia_*`、`bff`、`minMin_*`、`taskHead`、`stale`、`cur_time`、`maxDevTs` |
| BFF `probe` | `from_bff_sqlite`、`cache_hit`、`query_ms`、`row_count` 等 |
| 数据侧 | `flexibility_period_results.updated_at` vs `timestamp_minutes` 分析每仿真日墙钟 |

### 2.2 关键判据

```text
julia_total 小、bff/getData 大  → 排队 / 序列化 / 传输
rows_last 随历史暴涨            → 全量拉数
merge_avg 数十秒                → 前端合并
每仿真日墙钟间隔变大            → 写库/灵活性随历史变重
首次慢、第二次快                → JIT / 资源冷启动
```

### 2.3 分析脚本（示例）

- 读 `timeseries.db` 的 `flexibility_period_results`，按 `updated_at` 分批，算「每仿真日间隔」  
- 产物：`backend/data/tasks/<id>/flex_write_speed.svg` / `.csv`（任务目录内，非交付物）

## 3. 测试中发现的问题（按阶段）

### 3.1 开发期遗留（拖慢 run_task）

| 问题 | 影响 |
|---|---|
| 每步 `sleep(0.2)` | 恒定额外等待 |
| 每步 `write(generated/*.jl)` | 样本曾 589 文件 / ~4.6MB |
| 每步 `save_solve_trace!` 全量快照 | 与结果表重复写 |
| 热路径 `@info`（含每次 `set_ts`） | 控制台 I/O |
| `set_ts_merge` 整段读改写 | 序列越长越慢 |
| 组件每步 instantiate 两次 | 多余分配 |
| `_extract_layer` 反复 `deepcopy` | 内层循环浪费 |
| 前端大量 `console.log`、500ms 轮询 | 噪音与请求压力 |

### 3.2 数据链路 / 增量失效

| 问题 | 影响 |
|---|---|
| `/data` 全表导出所有点 | 曾 5万～10万行 JSON |
| 读写共用 `write_lock` | 前端读堵求解写 |
| `minTs` 含 `:` / BFF 丢参 / `query_params(req.url)` 解析失败 | 增量失效、偶发 500 |
| 水位被边界全年 `max(ts)` 拉到年末 | 设备新点拉不到 |
| `cur_time` 从未写入 | `taskHead=0` |
| `stale` 每 200ms 轮询 +1 | 误触发大窗全量 |
| BFF 缓存 key 含 `minMinutes` | 每轮 miss |
| SWR 只回旧缓存 | 图「假刷新」 |

### 3.3 前端渲染

| 问题 | 影响 |
|---|---|
| `findIndex` 合并 | 曾 **24～29s**/轮 |
| 浅更新 `liveData` | 子图 `watch(props.layers)` 不触发 |
| `JSON.stringify(liveData)` 做依赖 | 全量序列化 |
| 横轴锁在 `simEnd` 全年 | 设备曲线看起来不滚动 |
| 灵活性 period 增量后整包替换 | 只显示最近窗，不从 1/1 伸长 |

### 3.4 随历史变慢（根因）

| 问题 | 影响 |
|---|---|
| 查一点读全序列（`query_ts`/`get_ts`） | 单步 ∝ 历史长度 |
| 时序库膨胀 | 样例库约 **173MB** 量级 |
| 灵活性每仿真日批量 JSON upsert | 实测写入变慢 |
| 前端全历史 + ECharts 万级点 | 渲染变卡 |
| （曾）`optimize!` 占 Julia 事件循环 | HTTP 排队 |

**Flexibility 写入实测（任务 `b01abe82-…`）：**

| 阶段 | 每仿真日墙钟 |
|---|---|
| 前半 | **10.6 s** |
| 后半 | **34.7 s** |
| 倍数 | **≈ 3.27×** |

复测（另一任务 `6457022f-…`，优化后）：**3.62s → 9.54s / 日（≈ 2.63×）**——明显减轻，未消除。

### 3.5 冷启动

- Julia JIT（JuMP/HiGHS/SQLite/HTTP 首次路径）  
- Nuxt/Vite 首路由与大 chunk（编辑器 + Vue Flow + `component-library.json` ~98KB）  
- 首次读项目 JSON

## 4. 技术路线（总览）

```text
第一轮：少写、少传、读不堵求解、图能滚
  ├─ 关 generated/trace、降日志、sleep 0.2→0.1
  ├─ set_ts_merge 增量覆盖、组件只实例化一次、层配置缓存
  ├─ 增量 minMinutes + skipBoundary
  ├─ 点查（上层/爬坡/储能）+ series_id 缓存 + (series_id,ts) 索引
  ├─ Julia 结果内存快照
  ├─ BFF 直读 SQLite + SWR（key 不含 minMinutes）
  ├─ cur_time 回写、水位/stale 修正
  └─ 前端 Map 合并、dataVersion、图表引用 watch

第二轮：写批量、显示抽稀、冷启动、求解器
  ├─ A 一步结果单事务批量写
  ├─ B3 灵活性表索引（不砍明细）
  ├─ D 显示抽稀（小窗全精度）
  ├─ Julia warmup + 编辑器预取
  ├─ flex prepared statement
  ├─ merge 优先 append、少全量 sort
  ├─ ts_min 列
  └─ HiGHS / COPT + check_solvers.jl
```

**明确不做（业务约束）：**

- 不删除/降采样灵活性 **period 明细**（需全年明细）  
- 不做仿真历史归档裁剪（C3）  
- 不改调度数学与指标口径  
- 暂不做 PackageCompiler sysimage（过重）

## 9. 一句话总结

1. **体验主问题（前端不滚、全量拉数、merge 爆炸、读被求解堵）已解决。**  
2. **历史变慢主因是库写入（尤其灵活性明细）与长序列渲染**；已批量写/索引/ts_min/抽稀，**明细业务保留**，剩余约 **2.6×** 写入增长。  
3. **冷启动**用预热 + 预取缓解；sysimage 暂缓。  
4. **求解器**默认 HiGHS，可选 COPT。
