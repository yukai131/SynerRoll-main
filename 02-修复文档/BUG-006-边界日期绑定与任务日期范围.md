# BUG-006：边界日期绑定与任务日期范围

> 修复日期：2026-09-29、2026-10-04  
> 文档整理：2026-10-21  
> 状态：已修复、待回归验证；保留原记录的验证范围  
> 严重程度：P1  
> 影响范围：边界导入、日期元信息、任务创建、边界截取及结果日期展示

合并原主目录 BUG-006 和 BUG-007 的日期规则。2026-09-29 先引入 duration_only/calendar 双模式，2026-10-04 再统一为 calendar。本文明确区分历史阶段，避免把已撤销的“仅按时长”入口作为当前功能。能流及设备色部分分别归入 BUG-003、BUG-009。

## 1. 问题描述

用户导入无日期列的 24 小时或全年 CSV 后，希望仅仿真 7 月 1 日至 9 月 30 日，并查看自然日期坐标。原边界仅保存 0:00…H:MM，任务只能填写累计小时，seed 从序列开头截取，无法定位全年数据中的月份。补齐日期后，双模式入口、默认值和旧记录迁移仍不一致。

预期：所有边界统一绑定自然日期，无日期时默认从 2026-01-01 开始；任务在当前画布相关边界共同覆盖范围内选日期，后端精确截取，结果映射回真实日期。

## 2. 定位过程与历史证据

H1：BoundaryItem、boundary_config 缺少日期字段；H2：tasks 只有相对起止时间；H3：seed 使用 sorted_ts[1:truncate_count]，没有起始偏移。三项均经静态调用链确认；“只改前端输入框即可解决”被排除，必须同步修改类型、SQLite、任务和 seed。

## 3. 根因确认

系统原先只有相对时长模型，缺少“源序列索引 ↔ 自然日期”的契约。首次日期改造后的默认值和兼容路径仍保留双模式，使前端选项、SQLite 与旧项目语义不一致。

## 4. 修复方案与最终规则

### 4.1 统一日期与历史迁移

```typescript
export const DEFAULT_BOUNDARY_START_DATE = '2026-01-01'
export type BoundaryTimeMode = 'calendar'
```

边界元信息保存 timeMode、calendarStartDate、calendarEndDate 及长度、尺度、天数、点数。第一个点对应起始日 00:00，终止日由实际点数和尺度推导。日期空值提示统一为“年/月/日”，实际值保持 YYYY-MM-DD。

前端仅保留绑定日期；Julia 新导入固定 calendar。boundary_config 增加日期字段并迁移旧 duration_only 记录：缺失首日补 2026-01-01，按 day_count 推导末日。任务页读取旧项目元信息也归一化。迁移仅补时间元信息，不改时序值。

历史阶段曾将旧记录默认设为 duration_only，并允许典型日按时长使用；这已被后续迁移替代。24 小时典型日现在也解释为绑定起始日的一天。

### 4.2 任务日期与覆盖交集

- 只对当前画布相关边界求覆盖交集，无交集时拒绝创建。
- 创建任务的起止日期分行完整显示，“仿真日期”标签垂直居中；边界可选范围与仿真时长同一行展示。
- 请求和 tasks 表保存 simStartDate/simEndDate，同时保留求解兼容的 simStartTime="0:00"、simEndTime=包含天数×24:00。
- 历史无日期任务仍可使用原 H:MM 结果展示，不伪造其任务日期。

### 4.3 精确截取并重标局部时间

```julia
source_start_minutes = Dates.value(task_start_date - boundary_start_date) * 24 * 60
source_end_minutes = source_start_minutes + calendar_duration_minutes
selected_indices = findall(eachindex(sorted_ts)) do index
    source_minute = time_label_to_minutes(sorted_ts[index])
    source_minute >= source_start_minutes && source_minute < source_end_minutes
end
```

按任务起始日与边界起始日之差得到源序列偏移，用半开区间截取；再重标为任务局部 0:00…duration，保持现有模型和滚动时层语义。seed 优先使用当前画布节点 boundaryIds，旧项目无显式 ID 时回退 relatedComponents。

### 4.4 结果日期展示

任务信息栏显示自然日期；运行总览、能流、设备出力及灵活性图把局部分钟映射为 M月D日 HH:mm。日期粗选与滑块细调的状态、边界及颜色规则统一见 BUG-007。

## 5. 预期结果与副作用

| 场景 | 修复前 | 最终规则 |
|---|---|---|
| 全年 CSV | 无日期锚点 | 起始日及自动覆盖末日 |
| 7—9 月仿真 | 仍从源序列开头取值 | 92 天，按 7 月 1 日偏移截取 |
| 24h 典型日 | 相对时长 | 绑定起始日的一天 |
| 多边界范围 | 无一致性校验 | 共同覆盖交集内选择 |
| 旧 duration_only 边界 | 双模式默认值 | 迁移为 calendar，补缺失日期 |

当前按完整自然日选择，尚不支持非整日起止时刻。项目元信息与 SQLite 必须一致，seed 以 SQLite 为最终依据。没有日期的历史任务保持 H:MM；不能把边界迁移等同于重写所有历史任务。

## 6. 调试日志处理建议

[DATE]、parsed: 和 DATE-MODE 为一次性检查标记，不进入产品代码。现有 SEED 日志保留，记录系列数量和耗时；本次没有增加生产运行日志。
