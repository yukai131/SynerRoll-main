# BUG-004：上下调灵活性展示方向不直观

> 修复日期：2026-09-27
> 状态：待回归验证
> 严重程度：P2（体验问题）
> 影响范围：任务结果分析页的系统灵活性量化评估和设备灵活性量化评估图表；不影响灵活性计算、接口数据、汇总指标和其他分析模块

---

## 1. 问题描述

**用户操作路径**：

1. 创建并完成启用了灵活性量化评估的仿真任务。
2. 进入任务结果分析页的“系统灵活性量化评估”。
3. 查看上调、下调灵活性时序图，再进入“设备灵活性量化评估”查看设备曲线。

**预期行为**：上调灵活性在横轴上方以正值展示，下调灵活性在横轴下方以负值展示；用户可以直接根据曲线相对零轴的位置判断增加功率和减少功率的方向。系统级和设备级图表采用同一显示约定。

**实际行为**：上调和下调能力均以非负值展示。设备级上、下调曲线位于横轴同一侧，系统级下调供给和需求也显示在正值区域，必须依赖标题和图例才能判断调节方向。

## 2. 定位过程

### 2.1 初始假设

| 编号 | 假设 | 对应症状 | 初始置信度 |
|---|---|---|---|
| H1 | 后端将上下调能力都定义为非负容量，前端直接绘制原值 | 系统级下调曲线仍显示在横轴上方 | ⭐⭐⭐⭐⭐ |
| H2 | 设备图表纵轴固定从零开始 | 即使把下调数据改成负值，也可能无法完整显示 | ⭐⭐⭐⭐⭐ |
| H3 | 设备贡献分摊和并网边界曲线没有共享下调显示规则 | 主能力曲线与辅助曲线可能分处零轴两侧 | ⭐⭐⭐⭐ |

### 2.2 日志/调试方案设计

本问题是确定性的前端显示映射问题，没有运行异常、性能下降或随机数据偏差，因此未插入运行时调试日志。定位采用接口契约与图表数据流静态检查，并通过正式构建验证 Vue 模板和 TypeScript 编译。

后端明确要求 `device_flexibility` 为非负数，说明方向由 `direction` 字段表达，原始容量不应改为负值：

```julia

```

**检查位置 2**：`app/components/DeviceFlexibilityChart.vue` — 设备曲线取值和纵轴

修改前直接绘制上下调原值，并把纵轴最小值固定为零：

```typescript
.map(row => [row.timestamp, Number(row[field] ?? row.device_flexibility)])
```

```typescript
yAxis: {
  type: 'value',
  min: 0
}
```

**检查位置 3**：`app/components/FlexibilitySeriesChart.vue` — 系统曲线取值

修改前系统供给和需求直接使用后端非负容量：

### 2.4 分析与排除

**H1 被确认**：后端契约要求单设备灵活性和设备贡献为非负容量，系统图表和设备图表又直接使用这些值，因此两个方向原本都会显示在零轴上方。应在显示层根据 `direction` 转换符号，不能修改后端结果。

**H2 被确认**：设备图表原有 `yAxis.min = 0` 会排除负值区域，必须移除固定下界，交由 ECharts 根据正负曲线计算范围。

**H3 被确认**：设备能力、设备贡献和并网边界都经同一个 `valueByDirection` 取值函数生成。将方向映射集中在该函数中，可以保证全部设备级曲线采用一致规则。

后端计算错误被排除：`device_flexibility`、`device_contribution` 和 `system_supply` 的非负约束是既有接口契约，不是错误数据；本次不需要修改灵活性公式、结果 DTO 或存储内容。

## 3. 根因确认

根因是后端使用“非负容量值 + direction 方向字段”表达上、下调能力，而前端图表直接把非负容量绘制到纵轴，没有把方向字段转换为可视化符号。设备图表还将纵轴最小值固定为零，进一步限制了负值展示。对应修复位置为 `app/components/FlexibilitySeriesChart.vue:65`、`app/components/FlexibilitySeriesChart.vue:243` 和 `app/components/DeviceFlexibilityChart.vue:32`。

---

## 4. 修复方案

### 4.1 系统级方向映射

在系统灵活性图表增加纯显示函数。上调供给和需求保持正值，下调供给和需求乘以 `-1`；无效值返回 `null`，不把缺失值伪造为零。

```typescript
const directionalDisplayValue = (value: unknown): number | null => {
  const numericValue = Number(value)
  if (!Number.isFinite(numericValue)) return null
  return props.direction === 'down' ? -numericValue : numericValue
}
```

裕度和缺额继续使用后端原始评价值，避免改变 `margin = system_supply - requirement` 和 `deficit = max(0, -margin)` 的既有含义。移除系统图表纵轴的 `scale: true`，确保只有单侧方向数据时仍包含零轴。

### 4.2 设备级方向映射

设备图表在共用取值入口按方向转换符号：

```typescript
const rawValue = Number(row[field] ?? row.device_flexibility)
const displayValue = direction === 'down' ? -rawValue : rawValue
```

因此下调设备灵活性、下调系统供给分摊以及下调并网边界空间都会显示在横轴下方。上调曲线保持原值。

### 4.3 纵轴、汇总指标和显示边界

移除设备图表固定的 `yAxis.min = 0`，允许 ECharts 同时显示正负方向。`peak()` 仍读取后端原始容量，因此“峰值上调”和“峰值下调”继续显示非负容量值，不受图表符号映射影响。

符号转换只发生在 ECharts series 数据构造阶段，不写回 props、不修改接口响应，也不影响贡献度百分比和全时域汇总卡片。页面不额外增加读图说明。

## 5. 预期结果与副作用

| 指标 | 修复前 | 预期修复后 |
|---|---|---|
| 系统上调供给/需求 | 正值 | 正值，位于零轴上方 |
| 系统下调供给/需求 | 正值 | 负值，位于零轴下方 |
| 设备上调能力/贡献 | 正值 | 正值，位于零轴上方 |
| 设备下调能力/贡献 | 正值 | 负值，位于零轴下方 |
| 并网边界下调空间 | 正值 | 负值，位于零轴下方 |
| 峰值下调卡片 | 正容量 | 仍为正容量 |
| 后端结果与接口 | 非负容量 + direction | 不变 |

**副作用与限制**：

- 下调曲线的 Tooltip 会显示负值，这是新的方向展示约定；峰值卡片仍按非负容量展示。
- 系统级裕度和缺额保留原始评价符号，可能与下调供给、需求位于不同的零轴侧。
- 本次不修改颜色、主题、后端算法、结果 DTO、任务存储或其他分析页面。
