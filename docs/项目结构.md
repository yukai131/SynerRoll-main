# 代码与发行结构

以 `app/pages` 为前端页面入口；`app/components` 为编辑器、参数配置和图表，`config/component-library.json` 是前后端共用组件 schema。`state` 管理前端状态，`utils` 和 `composables/api` 处理画布、数据窗口及 API 请求。

`server/api/v1` 是 Nuxt/Nitro BFF。项目与方案应用记录为 JSON；时序、任务与容量规划结果由 Julia 的 SQLite 存储维护，部分结果由 BFF 用 Node 内置 SQLite 直接读取。`SYNERROLL_DATA_DIR` 统一两端数据根目录。

Julia 生产入口只有 `backend/server.jl`。它加载 core、组件的 `component.jl/model-common.jl/model.jl/flexibility.jl`、服务与路由。CHP 存在额外特殊校验，其他组件使用框架默认特殊校验和 schema 校验。求解器通过 `utils/model_utils.jl` 选择 HiGHS 或可选 COPT。

普通仿真链路：创建任务 → 项目快照解析 → 边界注入 → 分层滚动模型 → JuMP 求解 → SQLite 结果 → 经济评价/灵活性结果 → BFF 查询与 WebSocket 推送。

容量规划链路：检测容量变量 → 边界典型场景聚类 → 固定项目快照 → 独立 `capacity_worker.jl` → 候选容量的逐场景仿真 → 生命周期经济评价 → 搜索与结果落库 → 方案比较/应用/撤销。

Electron 首先显示本地许可证页面，通过后显示同风格启动页，并从安装资源启动内置 Julia 和 Node，健康检查成功后打开最大化主窗口。页面与图标位于 packaging/electron/ui，图标原文件位于 packaging/resources/logo-source.jpeg。安装资源通过白名单生成，不包含开发项目库、调试输出与测试。用户数据写入 `%APPDATA%\PSFA`。`packaging/scripts/build.ps1` 与 `electron-builder.cjs` 是唯一发行构建入口，`verify-installed.mjs` 用独立测试目录核验安装后的实际 API 与求解链路。

`docs/cleanup-manifest.txt` 记录删除的废弃项。修改前源文件和开发数据备份位于项目目录外的 `SynerRoll-before-packaging-20261022-154533.zip`。本目录原本没有 `.git`，因此没有生成提交或伪造 Git 差异。
