# BUG-005：缺少分时设备灵活性贡献图

> 修复日期：2026-09-27
> 状态：待回归验证
> 严重程度：P2（体验问题）
> 影响范围：任务结果分析页的系统灵活性量化评估图表；不影响灵活性计算、接口数据、设备级分析和其他结果模块

---

## 1. 问题描述

**用户操作路径**：

1. 创建并完成包含多类可调设备的灵活性量化评估任务。
2. 进入任务结果分析页的“系统灵活性量化评估”。
3. 查看上调、下调灵活性时序和右侧设备贡献度。

**预期行为**：除系统供给、需求、裕度和缺额曲线外，页面应按时间点展示设备灵活性贡献的堆叠柱。每根柱按风机、光伏、燃煤机组、气电机组、水电、储能、柔性负荷等实际出现的设备类型拆分，使用户能够判断某个时刻的灵活性主要由哪类设备提供。

**实际行为**：现有图表只能展示系统级时序曲线，右侧贡献度仅统计所选时间区间内各设备的累计占比，无法查看单个时间点的设备贡献构成及其变化。

## 2. 定位过程

### 2.1 初始假设

| 编号 | 假设 | 对应症状 | 初始置信度 |
|---|---|---|---|
| H1 | 后端逐时段结果没有返回设备贡献 | 前端无法生成分时贡献柱 | ⭐⭐⭐ |
| H2 | 前端只对整个可见区间累计贡献，没有按时间点重组数据 | 只能看到区间占比，无法判断某一时刻的构成 | ⭐⭐⭐⭐⭐ |
| H3 | 设备结果缺少稳定的类型字段 | 同类多台设备无法汇总为一种柱段 | ⭐⭐ |
| H4 | 新柱状图没有复用上下调符号约定 | 下调贡献可能仍显示在横轴上方 | ⭐⭐⭐⭐ |

### 2.2 日志/调试方案设计

本问题是确定性的前端展示能力缺失，不涉及随机运行异常或性能故障，因此没有插入运行时调试日志。定位采用结果 DTO 调用链和图表数据构造静态检查，并通过正式构建验证 Vue 模板和 TypeScript 编译。

**检查位置 1**：`app/components/FlexibilitySeriesChart.vue` — 区间贡献统计

修改前仅遍历可见区间并按设备累计贡献电量，用于右侧区间占比：

```typescript
for (const row of visibleRows.value) {
  const durationHours = Math.max(0, end - start) / 60
  for (const device of row.device_results ?? []) {
    const contribution = Number(device.device_contribution ?? device.device_flexibility)
    totals.set(key, {
      value: (current?.value ?? 0) + contribution * durationHours
    })
  }
}
```

**检查位置 2**：`backend/docs/灵活性说明文档.md` — 灵活性结果字段

逐时段结果已经包含：

```text
direction, device_id, device_flexibility, device_contribution, system_supply
```

其中 `device_contribution` 是按系统供给分配规则得到的设备实际贡献，前端无需修改后端接口。

**检查位置 3**：`app/components/FlexibilitySeriesChart.vue` — 系统图表

修改前组件只有一个系统折线图实例，series 仅包含：

```typescript
['系统供给', '系统需求', '裕度', '缺额']
```

**验证命令**：

```powershell
npm run build
```

### 2.4 分析与排除

**H1 被排除**：每条系统灵活性时段结果已经携带 `device_results`，其中包含设备实际贡献 `device_contribution`，无需扩展后端接口。

**H2 被确认**：原实现只按可见时间区间累计设备贡献并计算百分比，没有生成“时间点 × 设备类型”的二维数据，因此无法绘制分时堆叠柱。

**H3 被排除**：设备结果包含稳定的 `device_type` 和 `device_id`。可按 `device_type` 汇总同类多台设备，同时继续使用 `device_id` 完成右侧区间统计。

**H4 被确认**：后端贡献值为非负容量。下调图必须继续复用 BUG-004 的显示层方向映射，才能把下调贡献绘制在零轴下方。

---

## 3. 根因确认

根因是系统灵活性图表原本只实现了系统级折线和区间累计贡献度，没有把逐时段 `device_results` 按 `timestamp` 与 `device_type` 重组为堆叠柱序列。数据本身已经存在，缺少的是前端分时聚合与专用图表。对应修复位置为 `app/components/FlexibilitySeriesChart.vue:136`、`app/components/FlexibilitySeriesChart.vue:162` 和 `app/components/FlexibilitySeriesChart.vue:348`。

---

## 4. 修复方案

### 4.1 按设备类型生成稳定系列

扫描任务全部逐时段结果中的 `device_type`，生成稳定的类型集合和颜色映射。类型名称优先使用现有业务标签，未知类型保留后端类型代码，不用固定白名单丢弃新设备。

同一类型有多台设备时，在每个时间点对明确的 `device_contribution` 求和：

```text
某类型贡献(t) = Σ 该类型设备的 device_contribution(t)
```

缺少 `device_contribution` 的历史结果不使用 `device_flexibility` 代替，避免把理论能力误认为系统实际贡献；对应时段保持缺失状态。

### 4.2 增加独立分时堆叠柱状图

在每个上调、下调系统灵活性区块中，保留原系统折线和右侧区间贡献度，在其下方增加独立的“设备灵活性贡献构成（分时）”图表。全部设备类型使用相同 stack key，使每个时间点形成一根构成柱。

堆叠柱与现有折线共同使用 `visibleRows`，因此同一个双端时间滑块会同步控制两张图的显示范围。

### 4.3 延续上下调显示规则

上调贡献保持正值并显示在横轴上方；下调贡献只在显示层乘以 `-1` 并显示在横轴下方。后端原始贡献、区间贡献度和汇总指标不变。

### 4.4 Tooltip 与图例

Tooltip 显示当前时间、每类设备贡献功率、占当前时刻全部设备贡献的比例以及贡献合计，单位统一为 `kW`。比例分母使用该时刻完整堆叠总量，不因用户通过图例临时隐藏某个系列而改变。

图例按设备类型生成并支持滚动与点击筛选；颜色映射基于任务全部设备类型，因此上、下调图中同一类型保持相同颜色。

### 4.5 图表生命周期

组件为堆叠柱增加独立 ECharts 实例，复用现有 ResizeObserver，同时处理两张图的尺寸变化、时间轴悬浮事件和组件卸载释放，避免残留监听器或图表实例。

## 5. 预期结果与副作用

| 指标 | 修复前 | 预期修复后 |
|---|---|---|
| 单时刻设备贡献构成 | 无法查看 | 按设备类型显示堆叠柱 |
| 同类型多台设备 | 右侧分别累计 | 分时柱中按类型汇总 |
| 上调贡献 | 仅有区间统计 | 正值堆叠柱 |
| 下调贡献 | 仅有区间统计 | 负值堆叠柱 |
| 时间范围调整 | 只更新折线和右侧统计 | 同步更新折线、右侧统计和堆叠柱 |
| Tooltip | 无分时构成信息 | 显示类型贡献、占比、合计和 kW |
| 后端接口和计算 | 现有实现 | 不变 |

**副作用与限制**：

- 每个方向新增一个 ECharts 实例，页面高度和前端图表渲染开销有所增加；组件已统一处理 resize 和 dispose。
- 历史结果如果没有 `device_contribution`，堆叠柱显示“暂无设备贡献数据”，不会回退到理论灵活性。
- 颜色表包含八种颜色；设备类型超过八种时会循环使用颜色，仍可通过图例和 Tooltip 区分。
- 本次不改变系统折线、右侧区间贡献度、设备级灵活性页面、后端算法或结果 DTO。
