## 2. 应用记录结构（CapacityApplyRecord）

- 存储：`server/data/capacity-applies.json`（`server/utils/apply-store.ts`，与项目库同风格串行化写锁）；
- 状态机：`applied ⇄ undone`，每次切换记录当时的项目/画布版本时间；
- 快照：`canvasSnapshotBefore / canvasSnapshotAfter`（CanvasData 全量），撤销/恢复均基于快照整体替换（保留画布 id）；
- 安全校验：undo 要求目标画布 `updatedAt === canvasUpdatedAtApplied`；redo 要求 `=== canvasUpdatedAtUndone`（new-canvas redo 要求画布不存在）。
  项目级 `updateTime` 不做强校验——其他画布的无关编辑不应阻塞本画布撤销。

## 5. 待开发机回归

①应用（当前画布）→ 画布容量更新、记录 status=applied、验证任务创建且 canvasId=目标画布；
②应用（新画布）→ 原画布不变、新画布出现且容量为最优值、activeCanvasId 不变；
③事务性：人为制造第 N 台设备 componentKey 不匹配 → 409 且项目 updateTime 不变（无部分修改）；
④undo（当前画布）→ 容量恢复应用前值；应用后手动改画布再 undo → 409 拒绝；
⑤undo/redo（新画布）→ 画布移除/重建，activeCanvasId 回落与再指向正确；
⑥项目重新打开后应用记录仍在，undo/redo 可用（capacities.json 持久化）；
⑦记录落库失败场景：应用仍成功但响应 message 提示「撤销不可用」；
⑧双画布隔离：新画布应用不影响原画布的规划任务再应用（版本校验仍走 expectedProjectUpdatedAt）。
