# BUG-003：典型场景预览未绑定画布，跨画布边界混入聚类特征

> 修复日期：2026-09-27
> 状态：已修复、待回归验证（TypeScript/SFC 语法校验通过；Julia 侧本机无运行时，需在开发机跑双画布用例回归）
> 严重程度：P1 — 功能异常，双画布场景下规划输入口径错误且无任何报错
> 影响范围：同一项目存在多个画布、且各画布组件引用不同边界时的容量规划"典型场景"步骤；按 C-101 双画布测试条件必现
> 实施记录：第 4 节修复方案已按原样落地，共修改 7 个文件；`optimization_runner.jl` 实际运行时聚类调用点一并改为传入 `task["canvasId"]` 与任务快照，并新增"画布引用边界均不在边界库"的守卫报错

---

## 1. 问题描述

**用户操作路径**：

1. 在同一个项目中建立两个画布：画布 A（燃机 + 电负荷边界 L1）、画布 B（风机 + 光伏 + 电负荷边界 L2），两画布引用不同的负荷边界
2. 进入容量规划页，路由参数 `?canvasId=<画布A>`，完成第一步变量识别、第二步数据集检查
3. 第三步"典型场景"打开聚类特征下拉框，候选特征中出现了**仅被画布 B 组件引用的边界**（如 `单电负荷（L2）`、`风速 + 辐照度组合`）
4. 选择特征（或不选，留空）点击"预览典型场景"，聚类正常返回，但聚类输入中混入了画布 B 的边界序列

**预期行为**：

- 候选特征只列出目标画布（画布 A）节点所引用的边界；
- 预览请求携带 `canvasId`，后端拒绝或忽略不属于该画布的边界；
- 与 C-101 要求一致："form-schema、validate、scenario preview、planning create/config/start/result 全部增加 canvasId"、"边界选择只读取目标画布节点所引用的 boundaryId"。[01-武玉琨-容量设计软件详细计划.md](../04-后续开发计划/01-武玉琨-容量设计软件详细计划.md) 第 4 节

**实际行为**：

- 候选特征来自项目全部边界（`project.boundaries`），不按画布过滤；
- 预览请求体只有 `projectId`，没有 `canvasId`；
- Julia 端 `reduce_boundary_scenarios` 以项目为单位取全部边界参与聚类，不感知画布，全程无警告、无报错，结果静默错误。

## 2. 定位过程

### 2.1 初始假设

本问题属于**接口契约缺失类**，用户症状（候选特征越界、聚类口径错误）可由静态调用链直接证实，不需要运行时插桩日志；定位方法为"逐层追踪请求体与边界来源"。据此提出以下假设：

| 编号 | 假设 | 对应症状 | 初始置信度 |
|---|---|---|---|
| H1 | 前端候选特征列表未按目标画布过滤，直接取项目全部边界 | 下拉框出现画布 B 的边界 | ⭐⭐⭐⭐⭐ |
| H2 | 前端预览请求体缺少 `canvasId` | 后端无法感知画布 | ⭐⭐⭐⭐⭐ |
| H3 | BFF `scenarios/preview` 未校验、未补传 `canvasId` | 契约缺口在中间层放大 | ⭐⭐⭐⭐ |
| H4 | Julia `reduce_boundary_scenarios` 以 projectId 取全部边界，不做画布过滤 | 画布 B 边界序列进入聚类矩阵 | ⭐⭐⭐⭐ |
| H5 | 规划任务创建 BFF 同样未校验 `canvasId`，依赖后端兜底 | 同类契约缺口扩散 | ⭐⭐ |

### 2.4 分析与排除

**H1（候选特征未按画布过滤）被确认**：`clusteringFeatureOptions` 直接遍历 `project.value?.boundaries`，候选特征与画布无关。

**H2（预览请求缺 canvasId）被确认**：`previewTypicalDays` 请求体字段与 `ClusteringConfig` 类型均无 `canvasId`；同页 `validateForm` 已传，证明前端具备传入条件，属遗漏而非能力不足。

**H3（BFF 未校验未补传）被确认**：preview 路由缺少 form-schema/validate 路由中都存在的非空校验块，请求体原样转发。

**H4（Julia 未按画布过滤）被确认**：preview 路由无 `require_string(body, "canvasId")`；服务内 `actual_feature_ids` 与 `follow_ids` 均以项目全量边界为全集，featureIds 为空时（前端允许留空）必现全项目边界混入。

**H5（任务创建 BFF 未校验 canvasId）被确认**：`index.post.ts` 仅透传；所幸 Julia 侧 `create_capacity_planning!` 有 `isempty(canvas_id) && error("缺少 canvasId")`（`backend/services/capacity_planning/planning_manager.jl:160-162`）兜底，表现为 400 透传错误，不会造成串扰，但错误信息和校验位置不一致，应一并前移。

## 3. 根因确认

**根因**：典型场景（scenarios/preview）全链路缺失 `canvasId` 绑定——类型 `ClusteringConfig` 无该字段 → 前端不传 → BFF 不校验 → Julia 路由不要求、服务以 projectId 取项目全量边界参与聚类。

这直接违反两条已冻结契约：

- C-101："form-schema、validate、scenario preview、planning create/config/start/result 全部增加 canvasId"、"边界选择只读取目标画布节点所引用的 boundaryId"；[01-武玉琨-容量设计软件详细计划.md](../04-后续开发计划/01-武玉琨-容量设计软件详细计划.md) 第 4 节
- 接口契约："容量规划：当前 form-schema、validate、scenarios/preview、task CRUD、config、start、result、cancel、apply-and-simulate 形成完整骨架。**所有请求需补 canvasId**"；[05-数据结构与接口契约.md](../01-开发文档/05-数据结构与接口契约.md) 第 5 节

症状链条：候选特征越界（H1）让用户可以主动选到画布 B 的边界；即使不选（featureIds 为空），`reduce_boundary_scenarios` 也会把项目全部边界（含跟随边界）写进聚类矩阵和场景序列（H4），画布 B 的负荷/风速模式污染画布 A 的典型场景与权重，后续优化与结果在无任何告警的情况下基于错误输入计算——这正是 C-101 测试条件"同一项目建立两个画布，同时规划后结果不串"要拦截的故障。

---

## 4. 修复方案

原则：`canvasId` 与 form-schema/validate 保持同一契约形态（BFF 校验非空 + Julia `require_string`），Julia 侧以项目快照中目标画布节点引用的 `business.boundaryIds` 并集作为合法边界全集，对 featureIds 和跟随边界同时过滤。

### 4.1 类型补字段

**文件**：`types/capacity-planning.ts:85-95`

```typescript
// 修改前：
export interface ClusteringConfig {
  projectId: string
  datasetId?: string
  ...
}

// 修改后：
export interface ClusteringConfig {
  projectId: string
  canvasId: string          // ← 新增：聚类必须绑定目标画布（C-101）
  datasetId?: string
  ...
}
```

### 4.2 前端：候选特征按画布过滤 + 请求体补 canvasId

**文件**：`app/pages/capacity-planning/[projectId].vue`

```typescript
// 修改前（207、215 行附近）：
const configuredBoundaries = computed(() => project.value?.boundaries ?? [])
const clusteringFeatureOptions = computed(() => {
  const boundaries = configuredBoundaries.value
  ...
})

// 修改后：
// 当前画布节点引用的 boundaryId 并集（与 C-101"边界选择只读取目标画布节点所引用的 boundaryId"一致）
const canvasBoundaryIds = computed(() => {
  const nodes = project.value?.workspace.canvases.find(c => c.id === canvasId.value)?.nodes ?? []
  return new Set(nodes.flatMap(node => node.data.business.boundaryIds ?? []))
})
const configuredBoundaries = computed(() =>
  (project.value?.boundaries ?? []).filter(item => canvasBoundaryIds.value.has(item.id))
)
```

```typescript
// 修改前（1399-1410 行，previewTypicalDays）：
scenarioPreview.value = await planningApi.previewScenarios({
  projectId: projectId.value,
  ...
})

// 修改后：
scenarioPreview.value = await planningApi.previewScenarios({
  projectId: projectId.value,
  canvasId: canvasId.value,   // ← 新增
  ...
})
```

### 4.3 BFF：preview 路由校验并注入项目快照；task 创建补 canvasId 校验

**文件**：`server/api/v1/capacity-planning/scenarios/preview.post.ts`

```typescript
// 修改前（8-17 行）：
const body = await readBody<ClusteringConfig>(event)
await readProjectById(body.projectId)
const response = await $fetch<...>(JULIA_BACKEND_URL, { method: 'POST', body })

// 修改后（对齐 form-schema.post.ts 的写法）：
const body = await readBody<ClusteringConfig>(event)
const projectId = body.projectId?.trim()
const canvasId = body.canvasId?.trim()
if (!projectId || !canvasId) {
  throw createError({ statusCode: 400, statusMessage: 'projectId 和 canvasId 不能为空' })
}
const project = await readProjectById(projectId)
// Julia 需要项目快照来计算"画布节点引用的边界并集"
const response = await $fetch<...>(JULIA_BACKEND_URL, {
  method: 'POST',
  body: { ...body, canvasId, projectJson: project }
})
```

**文件**：`server/api/v1/capacity-planning/index.post.ts:12-15`（附带修复 H5）

```typescript

// 修改后：
```

### 4.4 Julia：preview 路由要求 canvasId，聚类服务按画布过滤

**文件**：`backend/routes/capacity_planning.jl:30-38`

```julia
# 修改前：
@post "/api/capacity-planning/scenarios/preview" function (req)
    try
        body = JSON3.read(req.body, Dict)
        data = reduce_boundary_scenarios(body)

# 修改后：
@post "/api/capacity-planning/scenarios/preview" function (req)
    try
        body = JSON3.read(req.body, Dict)
        canvas_id = require_string(body, "canvasId")   # 与 form-schema 路由第 7 行同写法
        project_json = get(body, "projectJson", nothing)
        project_json isa AbstractDict || return json_error("缺少 projectJson（项目快照）")
        data = reduce_boundary_scenarios(body, canvas_id, project_json)
```

**文件**：`backend/services/capacity_planning/scenario_reducer.jl` — `reduce_boundary_scenarios`（170、183、185 行附近）

```julia
# 修改前：
all_boundary_ids = get_all_boundary_ids(project_id)
...
actual_feature_ids = isempty(feature_ids) ? all_boundary_ids : feature_ids
follow_ids = setdiff(all_boundary_ids, actual_feature_ids)

# 修改后：
all_boundary_ids = get_all_boundary_ids(project_id)
# 合法边界全集 = 目标画布节点 business.boundaryIds 的并集
canvas_boundary_ids = _canvas_boundary_ids(project_json, canvas_id)
isempty(canvas_boundary_ids) &&
    error("画布 $(canvas_id) 的组件未引用任何边界，无法生成典型场景")
# 显式选择的特征必须属于目标画布
for fid in feature_ids
    fid in canvas_boundary_ids ||
        error("边界 $(fid) 未被画布 $(canvas_id) 的组件引用，已拒绝（请检查画布绑定）")
end
actual_feature_ids = isempty(feature_ids) ? collect(canvas_boundary_ids) : feature_ids
follow_ids = setdiff(collect(canvas_boundary_ids), actual_feature_ids)   # 跟随边界同样限制在画布内
```

配套新增私有函数 `_canvas_boundary_ids(project_json, canvas_id)`：从 `project_json["workspace"]["canvases"]` 找到目标画布，遍历 `nodes[].data.business.boundaryIds` 取并集；画布不存在时 error。

### 4.5 数据流对比

```text
修改前：
前端(全部边界候选) → preview{projectId} → BFF(透传) → Julia(项目全量边界聚类)
                                                        ↑ 画布 B 边界可混入，无校验

修改后：
前端(画布节点引用的边界候选) → preview{projectId, canvasId, projectJson}
  → BFF(校验非空) → Julia(require canvasId；合法全集=画布节点 boundaryIds 并集；
                    featureIds 越界即报错；跟随边界仅取画布内)
```

## 5. 预期结果与副作用

### 5.1 预期结果

| 指标 | 修复前 | 预期修复后 |
|---|---|---|
| 预览请求体字段 | 仅 `projectId`，无 `canvasId` | `projectId + canvasId + projectJson`，缺参返回 400 |
| 候选特征范围 | 项目全部边界两两组合 | 仅目标画布节点引用的边界 |
| featureIds 含画布外边界 | 静默参与聚类 | 明确报错并指出边界 ID |
| featureIds 为空时的聚类输入 | 项目全部边界 | 仅目标画布引用的边界 |
| 跟随边界（followIds）范围 | 项目全部边界 | 目标画布内、非特征的边界 |
| 双画布同时规划 | 场景可能互相污染，无告警 | 各画布聚类输入隔离，C-101 双画布用例通过 |
| 任务创建缺 canvasId | Julia 兜底 400，消息透传 | BFF 直接 400，错误位置前移 |

### 5.2 副作用

- **预览 API 契约变更**：请求体新增必填 `canvasId` 与 `projectJson`。前端同版本一起发布，无跨版本兼容负担（当前无外部消费者）；已在 draft 状态的规划任务，其 `config.clustering` 不含 `canvasId`，通过 `config.put` 修改聚类配置时应按任务自身的 `canvasId` 归一化补入（`_normalize_clustering_config` 已能拿到 `task["projectId"]`，同一处补 `task["canvasId"]` 即可）。
- **行为收紧**：此前"碰巧可用"的跨画布预览（用户主动选画布 B 边界）将变为 400 报错。这是契约要求的预期收紧，不是回归；报错信息中给出边界 ID 与画布 ID，便于用户修正绑定。
- **画布未引用任何边界时预览报错**：由"聚类全项目边界"变为明确失败。符合 C-101"边界选择只读取目标画布节点所引用的 boundaryId"，属预期行为，需在操作说明中写明。
