## 2. 与直接覆盖子版本的区别

- 保留主版本设备拟合、日期绑定、燃料价格与燃料成本目标、组件分类和图标、图表及灵活性功能。
- 保留主版本普通仿真和容量规划中已有的性能探针；容量规划 `simulation_evaluator.jl` 保持主版本原实现。
- 保留部署时可配置的 Julia 后端地址，新增接口不写死 localhost:8080。
- 保留旧 `financialParameters` 配置兼容，未采用来源版本删除该兼容分支的改动。
- 容量规划按项目算法中的求解器选择 HiGHS/COPT；仅选 COPT 时创建、复用和释放 COPT 环境。
- BUG-016 采用类型推断修正和合法网格量化，不将所有显式整数字段的小数输入自动四舍五入。主版本拟合字段校验继续有效。

开始融合前记录了主目录未提交状态和文件 hash。原有性能优化相关源码、图表、任务页和接口未被此次融合覆盖。工作期间另有组件图标、CanvasNode、组件 UI 配置及项目数据变更，未回滚或纳入此次容量规划移植。

## 3. 融合中修正的问题

1. **经济结果字典类型**：来源把现金流数组写入 `Dict{String,Float64}`，导致候选评价异常。改为允许结构化明细的字典；不可计算的回收期返回 null，不向 JSON 写 NaN。
2. **年度折算**：来源逐场景使用 `365/weightDays`，放大小权重场景。现先计算 `Σ(日值×代表天数)`，再统一乘 `365/Σ代表天数`，用于生命周期年度收入、成本及电量。优化的后验运行成本目标保留 `Σ(日成本×代表天数)` 口径。
3. **电量与价格**：发电量分母只积分 power，避免将燃料、弃电等系列误计为发电量；运行成本与主版本保持相同的边界价格优先、标量价格兜底及燃料投入推导规则。
4. **多画布经济口径**：只解析候选活动画布的经济组件；避免复制画布后复用节点 ID 导致重复投资和成本。
5. **全额退役**：候选容量为零时仍保留原设备处置回收，避免跳过整个 CAPEX 条目。
6. **配置链路**：补齐画布 ID、极端日开关、预览 hash、生命周期参数的保存与恢复；新注解缺省由服务端生成，旧草稿可继续校验。
7. **量化和预算**：允许 step=null；整数/档位吸附到范围内的合法值；结构约束失败计入评价预算和历史，避免大量拒绝候选时无限消耗优化调用。
8. **应用保护**：撤销/恢复同时核对画布版本和规范化内容，保护时间戳未更新的后续编辑；应用后前端重新获取项目数据。
9. **验证仿真接口适配**：两个版本的应用代码仍引用旧 datasets 接口，但当前规划页使用项目边界库。现在从目标画布引用的边界元数据取共同完整日期窗口；不要求 datasetId，旧值只保留作来源信息。返回日期和窗口循环补齐策略；没有共同窗口时在容量写入前拒绝。
10. **新画布验证目标**：创建验证任务时同时设置 canvasId 和请求快照的 activeCanvasId，避免普通仿真解析到原活动画布。项目本身的活动画布选择保持原状。
11. **接口与页面接线**：补齐 comparison 转发、类型导入及页面 class 绑定；修复极端日不足以形成普通聚类池的边界情况；清理未定义类型与新增容量页面类型错误。

## 5. 保留的子版本业务边界

- 七类目标是单目标选择；成组/互斥约束采用候选校验，IRR 约束采用来源版本的近似惩罚。
- 消纳率、绿电占比、购电占比、供需稳定性等技术约束的后验指标接线，在来源版本本身尚未完成；不能将配置项视为已经强制满足。
- 比较表的碳、可靠性、灵活性指标仍按来源说明展示缺失状态，不参与排名。
- 生命周期财务默认参数、售电价税假设、new 类型按候选总容量计投资等口径继承来源实现；本次手算测试验证实现一致性，不代替业务经济口径审定。
- 典型场景目前按日序号及一小时数据聚类；应用后验证仿真按主版本共同日历窗口运行。不同起始日期的边界在聚类阶段的绝对日期对齐仍需后续专项实现。

## 6. 实际使用后的终止、进度与经济窗口修复

用户实际多设备算例暴露了两项先前回归未覆盖的问题：取消信号只在候选边界检查，无法及时打断原生求解；日层结果为滚动计算保存了两天数据，后验经济服务重复统计了第二天。现已修复，详见：

- [BUG-010：终止与场景进度失效](../02-修复文档/BUG-010-容量规划终止与场景进度失效.md)
- [BUG-011：典型日经济评价重复统计](../02-修复文档/BUG-011-典型日经济评价重复统计.md)

规划改为独立 Julia 子进程，HTTP 后端只监督该进程。用户取消会停止本次规划并确认进程退出，其他普通任务不被终止；排队任务可直接取消；重复启动会被拒绝。页面显示当前候选/场景/阶段、持续更新的耗时和“正在终止…”状态。

总时限从子进程启动开始计时，包含模块加载和首次编译，不包括排队等待；单场景默认 60 秒。总时限到期时，保留完整候选中的最佳结果并提示未完成搜索；没有完整可行候选时明确失败。用户主动取消始终保持取消状态。场景触及限时而保有可行解时可参与规划评价，并明确注明未证明场景最优；普通仿真默认仍要求最优。

后验费用、售电收入、价格边界、松弛惩罚和电量均截取 `[0:00,24:00)`，原有滚动结果复制机制保持不变。历史结果未自动重算，需要重新规划。

追加验证：`backend/test_capacity_planning.jl` **99 项断言通过**，包含真实独立工作进程执行 HiGHS、原生阻塞取消（最后一轮 136 毫秒）、排队取消、重复启动拒绝、原子进度心跳、无完整候选超时、保有完整候选时超时与主动取消的区别，以及 48 小时数据的单日经济截取。原有 **10 项 Node 回归通过**，生产构建通过；容量相关 Vue/TypeScript 检查无新增错误，全仓原有类型问题仍保留。

`backend/test_capacity_solver_limit.jl` 另有 **4 项断言通过**，验证普通仿真仍拒绝限时结果、规划显式启用后仅接受已有可行解、没有解的限时结果仍被拒绝；合计 103 项 Julia 断言。

新进程控制需要**彻底重启 Julia 后端**，仅刷新前端页面或在原 Julia 会话中重新 include 不足以替换已加载的类型和旧工作线程。重启后刷新页面并创建新规划任务；旧版遗留的非终态记录会在新后端启动时标为中断失败。
