# 仿真性能优化（2026-10-19）

本轮针对“历史越长，整体推进和画面更新越慢”的数据链路修改。旧工作记录中的测量属于历史版本，本文件描述当前实现。

## 已修改

1. 灵活性精确基准读取使用 get_ts_exact；默认向前取值的适配器使用索引点查，保留无更早值时的错误语义。
2. 未启用预测算法时，边界与价格读取只取当前模型需要的时刻。floor 查询直接使用 ts_min，移除会妨碍复合索引的 COALESCE 表达式。
3. 完整内存快照改为按时间戳覆盖，不再每步复制和排序历史；BFF 直读的任务不额外维护该缓存。事务提交后才发布缓存变化，失败回滚不会污染缓存。
4. 时序接口支持 afterId/limit：依靠 AUTOINCREMENT rowid 获取追加和覆盖写入的变化点，在同一只读事务中获取数据与水位。覆盖过去的预测点也会获得新 id，不能用 max(ts) 替代这个水位。前端分批排空历史；终态确认后再读取一次，避免漏最后提交。
5. 窗口查询从 meta 定位序列，按 (series_id, ts_min) 范围读取。边界前缀使用精确 b_ 判断，修复 LIKE 'b_%' 误排除 BUS 的问题。运行总览按视窗分 48h 批次读取边界，全年数据保留在数据库。
6. 灵活性表增加 revision 与 (layer_id, revision) 索引，同事务递增版本。BFF 使用独立只读连接解析 JSON，不再与 Julia 写端争用应用锁。旧数据库不含版本时按快照兼容读取；Julia 首次使用旧库时执行增量迁移。
7. 前端直接合并 WS 变化点，约 250ms 合并一批；版本缺口使用 afterRevision 补查。WS、定时恢复、切页请求共用单在途控制，旧选择的响应不能覆盖新选择。
8. 经济性请求只在对应页面刷新，与曲线轮询解耦，避免主轮询等待经济性扫描；经济性序列和价格先在 SQL 中按覆盖范围截取。当前仍保留原有全量经济性公式计算，没有引入未经验证的增量财务汇总。
9. 使用 shallowRef 与持久索引，减少深层响应式遍历和历史数组复制；修复乱序插入使 ts→index 失效的问题。
10. 可见图表按动画帧合并更新，屏幕外只标脏；总览时间轴范围不再每轮展开全部点，绘制前二分截取窗口。抽稀极值按时间排序，保留原始数据和小窗口全精度；关闭实时曲线过渡动画。
11. 恢复默认关闭的缓冲阶段日志，并记录提交、应用和 ECharts finished 的版本。详见根目录《开发阶段性能日志说明》。
12. 修复任务事件广播中 Channel 检测异常被吞掉、导致 WebSocket 实际没有收到进度事件的问题。广播使用可用队列长度并限制缓冲，慢订阅者不会阻塞求解；客户端可通过版本补查恢复漏过的事件。

## 业务范围

未改变调度数学约束、目标函数、滚动执行顺序或灵活性指标口径。保留原有 0.1 秒主动等待。没有删除历史、压缩明细精度或迁移到另一种数据库。

启动预热继续保留。求解器模型复用、真正的 solver warm start、求解/API 分进程未在本轮贸然引入：需要根据分阶段测量单独验证，不能把所有后期增长都归因于数据库。
